# nuclei_parser_merged_improved.py – Documentation

## Overview

`nuclei_parser_merged_improved.py` is a Python script designed to organize and correlate Nuclei scan results into a structured report grouped by organization, root domain, and subdomains.

Unlike the default Nuclei output, which lists findings chronologically, this parser automatically correlates domains, subdomains, IPv4 addresses, mapped IP ranges, URLs, ports, and aliases belonging to the same organization into a single, easy-to-review report.

The parser is intended primarily for large External Attack Surface Management (EASM) scans, where thousands of findings must be reviewed efficiently while preserving the relationship between hosts and infrastructure.

---

## Features

### Automatic Input Detection

The parser automatically detects the input format and supports both:

* Standard Nuclei text output (`nuclei_scan.txt`)
* Nuclei JSONL output (`nuclei_scan.jsonl`) *(recommended)*

No configuration is required.

---

### Root Domain Grouping

All findings belonging to the same root domain are grouped together automatically.

Example:

```
example.com
www.example.com
mail.example.com
vpn.example.com
api.test.example.com
```

will be grouped under:

```
=== Root domain: example.com ===
```

while preserving every individual hostname.

---

### Mapping File Support

The parser supports custom organization mappings.

Example:

```
company.com,company.eu,company.org:1.1.1.1,2.2.2.0/24
```

Every finding related to:

* company.com
* vpn.company.com
* mail.company.eu
* portal.company.org
* 1.1.1.1
* 2.2.2.15

will automatically be grouped under:

```
company.com
```

This is particularly useful when organizations own multiple domains, aliases, or regional domains.

---

### Intelligent IPv4 Mapping

When Nuclei reports only an IPv4 address, the parser attempts to determine the correct organization using multiple techniques.

Priority order:

1. Exact IP mapping
2. CIDR mapping
3. IP range mapping
4. Forward DNS lookup
5. Reverse DNS (PTR)
6. Mapping specificity
7. Mapping file order

This significantly reduces incorrect grouping when multiple organizations share overlapping IP ranges.

---

### Automatic Root Domain Detection

Domains not present in the mapping file are grouped automatically using their registered domain.

Example:

```
portal.dev.example.co.uk
mail.example.co.uk
```

becomes

```
example.co.uk
```

Public suffixes are handled correctly.

---

### Subdomain Preservation

Although findings are grouped by their root domain, every individual hostname is preserved.

Example:

```
example.com

    mail.example.com
    vpn.example.com
    api.example.com
```

This allows findings to remain organized without losing host-level visibility.

---

### URL Parsing

The parser understands targets such as:

```
https://portal.example.com/login
https://vpn.example.com:8443
example.com:8080
```

It automatically extracts:

* hostname
* port
* path

while preserving the original URL in the output.

---

### Multiple Protocol Support

The parser is designed to process results generated by comprehensive Nuclei scans, including:

* HTTP
* HTTPS
* SSL
* DNS
* TCP
* UDP
* Network
* Headless templates
* Code templates
* Multi-protocol templates

---

### Duplicate Detection

Duplicate findings can be removed automatically while preserving all unique findings.

This significantly reduces report size when multiple templates generate identical results.

---

### Fallback IP Grouping

If an IP address cannot be associated with any organization, it is grouped into a configurable fallback network.

Default:

```
192.168.15.17

↓

192.168.15.0/24
```

This ensures that every finding is included in the final report.

---

## Mapping File Format

Example:

```
example.com:1.1.1.1

company.pl,company.eu:5.5.5.5,6.6.6.0/24

vpn.company.pl:10.10.10.10
```

Supported IP formats include:

Single IP

```
1.1.1.1
```

CIDR

```
1.1.1.0/24
```

IP Range

```
1.1.1.10-1.1.1.100
```

## Usage

### JSONL Input (Recommended)

```
python3 nuclei_parser_merged_improved.py \
    nuclei_scan.jsonl \
    ip_mapping.txt \
    -o nuclei_grouped.txt
```

### Standard Text Output

```
python3 nuclei_parser_merged_improved.py \
    nuclei_scan.txt \
    ip_mapping.txt \
    -o nuclei_grouped.txt
```

---

## Optional Parameters

Disable live DNS lookups:

```
--no-dns
```

Keep duplicate findings:

```
--keep-duplicates
```

Change fallback IPv4 grouping:

```
--ipv4-prefix 24
```

Change fallback IPv6 grouping:

```
--ipv6-prefix 64
```

Generate JSON output:

```
--json-output grouped.json
```

## Recommended Nuclei Scan

For best compatibility, it is recommended to perform scans using JSONL output and the complete Nuclei template collection:

```bash
nuclei \
  -l example.txt \
  -t ~/nuclei-templates/ \
  -headless \
  -code \
  -enable-self-contained \
  -enable-global-matchers \
  -fhr \
  -sa \
  -timeout 15 \
  -retries 2 \
  -c 30 \
  -bulk-size 20 \
  -headless-concurrency 5 \
  -headless-bulk-size 5 \
  -js-concurrency 40 \
  -payload-concurrency 20 \
  -rl 150 \
  -project \
  -stats \
  -stats-interval 15 \
  -jsonl-export nuclei_scan.jsonl \
  -o nuclei_scan.txt
```

## Best Practices

* Prefer **JSONL output** whenever possible. JSONL preserves structured metadata such as template IDs, protocol, severity, extracted values, matched URLs, resolved IPs, timestamps, and other fields that cannot always be reliably reconstructed from plain-text output.
* Keep the mapping file updated with known domains, aliases, IP addresses, and IP ranges to maximize grouping accuracy.
* Use the parser after comprehensive Nuclei scans that include HTTP, SSL, DNS, Network, Headless, and Code templates to obtain the most complete results.
* Periodically review fallback IP groups to identify infrastructure that should be added to the mapping file.
* Leave duplicate removal enabled (default behavior) to produce concise reports while retaining all unique findings.
* When overlapping IP ranges exist in the mapping file, the parser automatically selects the most likely organization using DNS resolution, PTR records, mapping specificity, and mapping order, minimizing incorrect attribution.
* The parser preserves the original target (URL or hostname), extracted port, path, and associated metadata, ensuring that no context is lost during grouping.
